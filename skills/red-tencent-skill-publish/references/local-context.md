# 本地 Private Reference 契约

需要识别账号、找到已有条目、复用本机环境或登记发布结果时读取。公开流程与私人事实分开存储，发布使用公开副本，不复制私人记录。

## 位置与内容

私人文件固定在 `${CODEX_HOME:-$HOME/.codex}/private/red-tencent-skill-publish/context.md`，位于安装 Skill 与公开仓库之外。其它客户端可选等价的本机私有目录，先记录所选位置。目录权限 700、文件 600；不放进 Git 跟踪或同步的 Skill 目录。

记录平台账号标识、浏览器配置标识、原条目 ID／identifier／slug、展示名、分类、原创归属、源版本、本机 CLI／官方凭据文件的位置、最近验证时间、审核回执和下一步。只记录“凭据由哪个官方文件管理”与授权结果，不记录密码、token、cookie、验证码、二维码、完整凭据文件或敏感账号截图。

入口模板是公开的 [assets/private-context.template.md](../assets/private-context.template.md)，只含字段和占位提示。首次确需持久化时在私有目录创建个人副本；已有文件则只更新本次目标事实，不覆盖其它记录。使用者可以照此建立自己的 Private Reference，无需修改公开 Skill。

## 读取与更新

- 先读取本次指定平台与条目所需记录，避免把其它私人信息带入上下文或日志。文件不存在时仍可检查公开流程和打包，只在缺少发布所需身份时询问。
- 每条状态带核验时间和来源；账号归属、当前版本／审核、工具和授权状态在外部操作前核实。私人记录是定位线索，不能替代当前平台事实或用户本次授权。
- 提交后登记目标、版本、回执和审核状态；审核通过后再登记公开版本。失败只记录非敏感错误与恢复下一步，不保存 HTTP 认证头或全部响应。
- 聊天中仅报告完成与所需决策；不整段展示私人文档。确需公开的作者署名或来源由用户决定，不能因为账号已在本机保存就自动填入公开简介。

## 发布隔离

实际 `context.md`、`private/`／`.private/`、`PRIVATE.md` 和 `*.private.md` 不纳入发布清单，不能仅依赖 `.gitignore`（它不控制 CLI 上传）。用 [公开打包](public-package.md) 的显式文件清单制作干净副本，核对 Git 暂存与平台最终包。模板可公开，个人副本不能公开。发现历史包含私人信息时停止新提交，说明具体范围并按权限处理原包。
