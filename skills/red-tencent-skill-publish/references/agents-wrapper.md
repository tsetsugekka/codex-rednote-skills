# 将 AGENTS 规则包装为平台 Skill

源为 `AGENTS.md` 或它按需引用的规则专题，且目标是 RED Skill／腾讯 SkillHub 时读取。目标是添加可用的发布入口，保留规则底稿；不是把长规则改写成常驻 Skill 或全局 AGENTS。

## 源与平台副本

- GitHub 可保留 AGENTS 文件及专题目录；AI Hub 在支持 AGENTS 类型的入口按原形态发布。是否同步这些平台、语言和原创／转载来源，仍取用户本次指定，不因包装自动扩大发布范围。
- RED 与腾讯包根需要 `SKILL.md`。在临时发布副本中新增简短入口，把完整公开规则放在 `references/AGENTS.md` 或原专题名（如 `references/FRONTEND-DESIGN.md`），不要只改扩展名或复制一份空入口。
- 底稿与专题文档继续是权威来源。后续版本从同一源同步正文、入口、页面简介与更新说明；不从旧平台副本反向覆盖底稿。只公开用户指定主题，排除凭据、私人偏好及内部记录。项目专属要求留在项目文档，可复用经验才进入公开规则。

## 入口与引用

`SKILL.md` 的 frontmatter 含 `name`、`description`；正文说明适用触发、先读哪份完整规则、如何在任务中使用，以及关键权限边界。名称与摘要如实说明它是规则集的读取入口，不声称新增源中没有的能力。

例如，前端专题的短入口可以是：

```markdown
---
name: frontend-rules-assist
description: 在界面设计、前端改版、加载性能或 SEO 任务中按需读取并应用前端规则。
---

# 前端规则入口

处理上述任务前，读取 [完整前端规则](references/FRONTEND-DESIGN.md)，按当前任务适用章节执行。
规则只在对应任务中调用；如需加入项目 AGENTS，按用户要求添加短触发入口，完整正文仍独立保存。
发布或安装此包不自动修改全局 AGENTS、启用钩子或授予部署权限。
```

包装不授权修改用户全局配置、安装依赖或发布其它平台。源规则要求哪些工具就如实说明；已可独立执行的规则不加上“必须先安装某个 Skill”的条件。

复制本次需要的全部公开引用文档和资源，调整副本内相对链接，使其从新目录可解析。不要摘要替代完整正文；正文较长也不截断，而由短 `SKILL.md` 按需导航。按 [中文发布副本](publishing-language.md) 完整翻译自然语言说明，保留原规则、命令和限制。

## 提交前验收

- 根入口合法、有真实触发条件且能读到完整规则；引用闭包齐全，无本机绝对路径或跳出包外的依赖文件。
- 发布正文与指定源版本逐项对应，引用路径调整及翻译不改变执行范围和含义。
- 来源、许可证、原条目 ID／slug 保留。拥有 GitHub 仓库不等于“GitHub 导入”：用户自己的规则可按原创发布，不擅自登记为 GitHub 来源。
- 添加包装后分别执行 [RED 流程](red-workflow.md)／[腾讯流程](tencent-workflow.md)，核对平台字段、图标需求和最终文件清单。首次腾讯带图标仍走网页；包装不改变提交／审核／公开生效的区别。

## 已验证做法

前端规则专题曾在 GitHub、AI Hub 保持 AGENTS 形态，在腾讯发布为根 `SKILL.md`、README 和 `references/FRONTEND-DESIGN.md` 的包；完整规则仍按需读取，用户指定原创且未登记 GitHub 来源。该案例说明平台格式适配可以与规则底稿分开维护；具体业务要求和其它平台发布授权不从案例继承。
